2. DESIGN DOCUMENTATION (Conflict Key, Transaction Boundary, Index Choice)
========================================================================
A. Conflict Key Choice (`event_key`):
   - `network_events` defines `event_key TEXT NOT NULL UNIQUE`, storing a deterministic
     SHA-256 hash of all 11 CSV fields joined with `|` (`timestamp|sensor_name|src_ip|
     dst_ip|src_port|dst_port|protocol|event_type|action|bytes|duration_ms`).
   - Unlike surrogate `event_id` or non-unique pairs like `(src_ip, timestamp)` (multiple
     events can share the same second and source IP), `event_key` uniquely identifies
     the exact event payload.
   - `ON CONFLICT(event_key) DO NOTHING` with `executemany()` makes batch ingestion
     fully idempotent: new rows are inserted while duplicate rows in retried batches are
     ignored without throwing `IntegrityError` or duplicating records.

B. Transaction Boundary (`BEGIN TRANSACTION` ... `ROLLBACK` / `COMMIT`):
   - In SQLite, triggers (`log_alert_status_change`) run inside the same transaction as
     the statement that fired them (`UPDATE alerts`).
   - Wrapping the status update in an explicit transaction guarantees atomicity between
     `alerts` and `alert_status_history`: either both commit together, or `ROLLBACK`
     reverts both the status update and the audit record written by the trigger.

C. Index Choice (`idx_events_src_time` on `network_events(src_ip, timestamp)`):
   - Incident investigation queries filter by `src_ip = ?` over a time range
     (`timestamp BETWEEN ? AND ?`) and sort by `timestamp`.
   - Without `idx_events_src_time`, SQLite performs a full table `SCAN` plus an external
     sort (`USE TEMP B-TREE FOR ORDER BY`).
   - With the composite B-tree index `(src_ip, timestamp)`, SQLite performs an index
     range `SEARCH` and reads rows already sorted by `timestamp`, avoiding both the
     full scan and the temporary B-tree sort.
